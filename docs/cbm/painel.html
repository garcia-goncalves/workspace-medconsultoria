As peças mais reutilizadas

Quantas partes diferentes do sistema dependem de cada uma. São as peças que não se mexe sem cuidado: um erro aqui aparece em dezenas de telas de uma vez. Também é o sinal de que o código não está duplicado — a mesma peça serve o sistema inteiro.

Como ler: cn é usada por 90 partes porque é o utilitário que monta o estilo de quase todo componente visual. notificar aparecer com 25 significa que aviso ao usuário passa por um único lugar — foi decisão de projeto (ADR-16), e é por isso que dá para mudar o texto de todos os e-mails num ponto só.

Onde o código é mais difícil

"Complexidade cognitiva" mede quanto raciocínio uma função exige de quem a lê — condições dentro de condições, laços aninhados, muitos caminhos. Não é bug, é risco: quanto maior, mais fácil alguém errar ao mexer, e mais difícil testar.

O retrato geral é bom: a média é 2,3 e a mediana é 0 — a esmagadora maioria das 1.190 funções é simples. Só 37 passam de 15. O problema está concentrado, não espalhado: NovoDocumentoDialog sozinho tem 751 linhas e complexidade 114, três vezes o segundo colocado. Se um dia valer a pena refatorar alguma coisa, é ele — e só ele.

Como as partes conversam

Quantas chamadas cruzam a fronteira entre os pacotes do projeto. O desenho previsto é a tela usar os componentes visuais e os tipos compartilhados, e o motor usar os mesmos tipos — nunca o contrário.

O desenho está sendo respeitado: as setas vão todas de quem usa para quem é usado (web → ui, web → shared, api → shared). Não existe ui → web nem shared → api, que seriam dependências circulares — o tipo de coisa que trava um projeto com o tempo.
